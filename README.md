# 古法纸浆入缸账

纸浆发酵的入缸账：事件溯源（event sourcing）。浸泡缸、纸浆批次、观察补录不再挤在同一条记录里，而是拆成**事件日志**与**派生状态**两层。

## 规则

- **事件是唯一事实来源**：建档、观察补录、换缸、备注都是事件；缸位、发酵天数、异常标记、状态全部由事件重算，断电后重启自动重算，状态与事件账始终一致。
- **现场单号幂等**：每条观察/换缸带现场单号（`serial`），重复补传只认第一次，回网重放不会多记一天。
- **乱序与更正**：补录按观察时间排序重算天数；旧记录填错可提交更正事件，天数不重复、状态重算。
- **缸位容量**：换缸占用目标缸容量（默认每缸 1 批），缸满时换入返回 `409 vat_occupied`，**原批次保留不动**，响应带 `retryable` 可重试；建档占缸同理。
- **冲突锁定**：缸位超容或现场单号跨批次重复 → 涉及批次标记冲突、状态锁为「异常观察」，不可抄纸；资料不完整（缺原料/负责人/缸位）同样锁定。
- **可抄纸条件**：资料完整、无冲突、无异常且发酵满 7 天。
- **串行写入**：所有读-改-写排队执行，夜班/白班两个终端同时提交不会互相覆盖。
- **旧数据升级**：旧版 `items` 格式首次启动自动迁移为事件账（`schemaVersion: 2`），旧批次保留可查，原天数/状态留在 `legacy` 字段。

## 运行

```bash
npm start
```

访问 `http://localhost:3039`。数据保存在 `data/paper-pulp-fermentation.json`，写入采用临时文件 + 原子替换。

## 接口

- `GET /api/items` — 批次列表（派生状态 + 事件日志）
- `POST /api/items` — 建档（占缸，缸满返回 409）
- `GET /api/items/:id` — 单批次
- `POST /api/items/:id/observations` — 观察补录（需 `serial`，幂等）
- `POST /api/items/:id/observations/:serial/correct` — 更正旧观察记录
- `POST /api/items/:id/vat` — 换缸（需 `to`，可选 `serial` 幂等；缸满 409 且原批次不动）
- `GET /api/vats` — 缸位容量与在养批次
- `GET /api/stats` — 状态统计（含冲突数）
